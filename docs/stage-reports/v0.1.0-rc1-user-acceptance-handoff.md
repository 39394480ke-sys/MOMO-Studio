## Safety architecture

- Defaults are `DRY_RUN`, hardware `DISABLED`, Real motion false, commissioning motion
  false, empty physical-unit identity, and Synthetic-only camera.
- Motion routes through one Motion Safety Gateway; routes and Vision do not reach drivers.
- `COMMISSIONING_READ_ONLY`, `COMMISSIONING_MOTION_TEST`, and `REAL_MOTION` are separate,
  non-upgradeable session purposes.
- Commissioning motion is backend-limited to one explicitly armed relative joint test
  under an immutable envelope and backend deadman.
- Capability evidence is exact-unit/fingerprint bound and independently staged.
- Old/manual global Field Acceptance `PASSED` is non-authoritative.
- Feetech goal write, Physical Stop, and Real Kinematics remain fail closed.
- Browser authority uses an HttpOnly same-origin cookie; raw tokens are not placed in
  JavaScript state, URL, browser storage, or audit logs.

## User acceptance instructions

1. Use the final Draft PR head and the default copied local configuration.
2. Keep all checks in Dry Run and use Synthetic Vision only.
3. Complete [the software checklist](../user-acceptance-checklist.md).
4. Record `ACCEPT`, `ACCEPT WITH ISSUES`, or `REJECT`, with issue notes and reproduction
   steps where applicable.
5. Do not perform Real-hardware field steps as part of software acceptance.

## If the user selects ACCEPT
