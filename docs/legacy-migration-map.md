# Legacy migration map

## Source and audit boundary

- Legacy repository: `https://github.com/39394480ke-sys/MOMO_RobotARM.git`
- Reference branch: `V2`
- Audited commit: `ff8bbda0c2222cb57951c7913f7f12f5777b98fa`
- Audit date: 2026-08-23
- The commit above is the evidence boundary for every path and line reference below. The Legacy checkout was read only. No Legacy program, hardware dependency, serial discovery, calibration operation, or motion command was run.
- Stage 1 copies no Legacy implementation or binary asset. It records behavior, contracts, safety invariants, provenance, and later verification work only.

`Disposition` has exactly four allowed values:

- `REUSE`: a small, isolated behavior may be carried forward only after provenance review and characterization tests.
- `ADAPT`: retain the demonstrated behavior or contract, but reshape it behind the new ports and schemas.
- `REWRITE`: reimplement from the extracted contract because the Legacy boundary is incompatible with the target architecture.
- `RETIRE`: intentionally do not migrate the capability.

`OUT_OF_SCOPE` appears only as a scope annotation. It is never a `Disposition` value.

## Data and configuration evidence

- Canonical-looking Legacy action files are not canonical new data. `动作库/V1演示.json:2-13` declares V1 with J11-J15; `动作库/v2 演示.json:2-14` declares V2 with J10-J15. Older V1 examples instead use `shoulder_pan` through `wrist_roll` (`动作库_示例备份_不要真实运行/示例_录制动作.json:2-13`). Every audited action JSON also contains a gripper section. No action JSON was copied.
- The Legacy calibration examples are templates, not production calibration. Structurally, both `标定/v1.example.json` and `标定/v2.example.json` declare their variant but contain J10-J15 plus a gripper key (`v1.example.json:2-10,18-58`; `v2.example.json:2-10,18-58`). No numeric calibration value was transcribed.
- The audited Git index contains a local-backup calibration artifact under `真实舵机控制/标定/标定备份_backups/`, even though `.gitignore:16-19,42` intends to exclude local JSON and calibration backups. Its contents were deliberately not read. It is `RETIRE`, has no target module, and must never be copied, summarized, logged or committed in MOMO Studio.
- Runtime state, logs, serial-port overrides, `.env` contents, local calibration, captured media and user recordings are migration inputs only after explicit per-file review; they are not source artifacts.

## Migration gates

Before any later migration PR can change a disposition into implementation work, it must include:

1. The pinned Legacy SHA and exact source paths/functions.
2. Provenance/license clearance for every copied line or asset.
3. Characterization tests that demonstrate the intended Legacy behavior without hardware.
4. A conversion plan into explicit `RobotProfile.enabled_joints`, typed units and the new immutable Pose Snapshot/Motion schemas.
5. A deny-by-default safety review for variant, calibration fingerprint, joint/raw range, non-finite data, stale vision and cancellation/Stop behavior.
6. Evidence that no serial port, local calibration, runtime state, secret, captured media or user-specific path entered Git.
7. Confirmation that the change does not introduce any capability in the retirement register.
